# Changes on top of ROCKNIX

"Deep sleep plan" and "Projects to learn from" are in [sleep.md](sleep.md).

Until 2026-10-10 each change was a merge request; their write-ups (what was broken, why, what changed) are in [merge-requests.md](merge-requests.md). Later changes are plain commits whose messages say the same.

The numbers below, such as `0001` or `9018`, are the old patch files. Each is now one commit: search this repo's log for "Asgard patch NNNN", and the `asgardos/linux` log for the kernel's, whose subjects keep the patch's file name.

| Change | Why |
|---|---|
| Updates from GitHub (2026-11-21) | An update reached a Thor only by copying a 1.7 GB `.tar` into `/storage/.update` by hand. `asgard-update.py` now reads GitHub's releases list (no device data), picks the newest `vX.Y.Z` above `OS_VERSION` that has this device's `.tar`, `.sha256` and `.sig` (pre-releases count: every release so far is one), downloads it with curl to a `.part` it resumes, and renames it to `.tar` only once the sha256 matches and the `.sha256`'s Ed25519 signature matches the key in the image: the checksum alone comes from the same release, so it catches a broken download but not a replaced one. The signature covers the `.sha256`, not the `.tar`, because Ed25519 signs a message whole, and it's checked before the `.tar` is fetched, so a release signed with another key costs two small files, not 1.7 GB. `asgard-update-check.service` checks once a boot, without holding the boot up; Home asks once (Download / Later / Skip this version, a third button on its confirm dialog) and again when the download is ready; Settings > About > Updates has the rest. Installing is offered on the charger or at 30% or more. `scripts/release` signs a release (UPD-9, UPD-10, DEV-22, SET-3). `test_asgard_update.py` against a local server, `test_home_update.py`. |
| WireGuard split tunnels don't take all DNS (2026-11-21) | After a reboot every name lookup on a Thor failed (the scraper said "No internet"): NetworkManager makes an imported WireGuard tunnel the DNS default route, taken from the Wi-Fi, and a `.conf` with `DNS =` also gets the catch-all routing domain `~.`. The tunnel came up at boot before it had resolved its hostname `Endpoint`, so that lookup went into the tunnel itself and failed, and so did every lookup after it. A tunnel that doesn't carry all traffic (no `0.0.0.0/0` or `::/0` in `AllowedIPs`) is now switched on with `ipv4/6.never-default yes` and no catch-all: the Wi-Fi keeps the DNS default, the tunnel's DNS server is still configured on its link. On a Thor, `never-default` alone moved the DNS default back to the Wi-Fi; lookups then worked with the tunnel's peer pointed at a dead address, and after a reboot the tunnel found its endpoint with nothing touched. A tunnel that was already imported gets this the next time it's switched on (NET-3). `test_home_settings.py` runs the command against a fake `nmcli`. |
| ScreenScraper sign-in, through Skyscraper (2026-11-21) | Descriptions came only from ScreenScraper, whose API needs a developer ID that Asgard doesn't have (requested only through their forum), so only PS1/PS2 had any, and Switch had no art at all. Skyscraper (3.21.1, GPL-3, as RetroPie ships it; `packages/apps/skyscraper`, built with qmake6 on the image's Qt 6) carries its own developer ID, so a user needs only their free ScreenScraper account: Settings → Library → ScreenScraper account saves it (`screenscraper.username` / `.password`, the keys `asgard.yml` already took). `asgard-scrape.py` then runs Skyscraper for the one game, with the login in a private temporary `config.ini` rather than on its command line. Skyscraper rewrites a whole gamelist with only the games it was given, so it writes into a scratch folder and only that game's entry and art (cover, screenshot, wheel as marquee, through our `asgard-artwork.xml` instead of its default montage) are copied over; its details replace older ones, but a name the user set stays. libretro still adds a cover ScreenScraper lacked (SCRAPE-1). `test_asgard_scrape.py` runs a fake Skyscraper; `test_home_scrape_missing.py` the sign-in. |
| Scraper finds games again, Scrape missing (2026-11-21) | Scrape this game found nothing for any game: thumbnails.libretro.com, where it listed each system's art and guessed a match from the file name, now serves an empty index and a 404 for every path (0 of 395 games on a real library). The art is still in libretro's GitHub repos, which have no listing to guess from. The image now holds an index of libretro-database (names, CRCs, developer, publisher, genre, date, players, PS1/PS2 descriptions; 13 MB, built by `asgard-scrape.py --index` in the `asgard` package). A game is looked up by CRC (a zip's from its header; files under 64 MB), then by name, and its art is fetched from `raw.githubusercontent.com/libretro-thumbnails` by its exact name, trying the same game's other regions when one has no art. The details go into the gamelist without overwriting what's there. Names alone now match 374 of 395. Settings → Library → Scrape missing runs it for each game without a cover (SCRAPE-1). `test_asgard_scrape.py`, `test_home_scrape_missing.py`. |
| Release numbers (2026-11-21) | The version was ROCKNIX's build date (`OS_VERSION=$(date +%Y%m%d)`), so every build was a new "version" and About couldn't say which release a Thor runs. It's now a release number, `0.0.1` first, set by hand in `distribution/version`; builds between releases differ by commit and date, which About shows too (SET-6). `usbgadget` read the gadget's `bcdDevice` from the date's digits; it now packs major.minor.patch (`0x0001`). `build.sh stage` took the alphabetically first `.tar`, which no longer means anything: it takes the newest. `test_version.py`. |
| Gyro files from the Thor's own Android (2026-11-21) | The gyro worked only after copying its HexagonFS root (DSP libraries, sensor configs, this unit's calibration) out of Android by hand, with no tool to do it, so on most Thors it never ran. Those files are still on the Thor: `dsp_a` and `persist` are ext4 partitions, `vendor` and `odm` ext4 images inside `super`. `asgard-sensors-root.service` (`asgard-sensors-root.py`) now builds the root once at boot, before `thor-sensorspd`, mounting them read-only (`ro,noload`), copying what the sensors PD reads (the three `rfsa/adsp` libraries the working root had, not the 350 MB of camera/NPU models), the device info Android's `soc0` had (Thor constants and the live serial), and our path map. Built beside the target and renamed, so the service never sees half a tree; a root already there is left alone (INP-1, CFG-7). `test_sensors_root.py` reads a synthetic `super`. |
| Games card is never another install (2026-11-21) | Booted from a card, `automount`'s games-card search also looks at the internal disk and mounted the first big unmounted partition it found, an internal install's `STORAGE`, at `/storage/roms`, writing a `roms` folder into it: the card and the internal install mounted each other's partitions after all (UPD-8; the same mount was seen 2026-10-07). A ROCKNIX card in an internal Asgard was taken the same way. The search now skips any partition labelled `ASGARDOS`, `STORAGE`, `ASGARDSD`, `STORAGESD` or `ROCKNIX`; a games-only card is mounted as before (`test_automount_os_partitions.sh`). |
| SD card labels of its own (2026-11-20) | A card flashed with the release image booted the internal install instead of itself: both carried the labels `ASGARDOS`/`STORAGE`, the entry asked for `boot=LABEL=ASGARDOS disk=LABEL=STORAGE`, and init took the first match, the internal UFS (seen 2026-11-14 and 2026-11-20). The SD image now labels its partitions `ASGARDSD`/`STORAGESD` (`IMAGE_*` in `distribution/options`) and its entry names them (`mkimage_abl`); the system image's entry keeps `ASGARDOS`/`STORAGE`, so installed Thors are unchanged (UPD-5). `installtointernal` points the entry it copies from the card at the internal labels, and `update.sh` keeps the `boot=`/`disk=` a device already boots with, since every update copies the shipped entry over `/flash` (UPD-8). `test_boot_labels.py` runs the real `mkimage_abl` and `update.sh`; `test_install_to_internal.py` checks the copied entry. |
