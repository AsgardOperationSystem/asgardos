# Changes on top of ROCKNIX

"Deep sleep plan" and "Projects to learn from" are in [sleep.md](sleep.md).

Until 2026-10-10 each change was a merge request; their write-ups (what was broken, why, what changed) are in [merge-requests.md](merge-requests.md). Later changes are plain commits whose messages say the same.

The numbers below, such as `0001` or `9018`, are the old patch files. Each is now one commit: search this repo's log for "Asgard patch NNNN", and the `asgardos/linux` log for the kernel's, whose subjects keep the patch's file name.

| Change | Why |
|---|---|
| Kernel 7.3.1 (2026-10-30) | Rebased from 7.2 as commits (pushed to `asgardos/linux`). Dropped, already in 7.3: `9007`, `9039`, the QCE runtime-PM series, 7.2 `0011` (adc-tm5) and `0016` (DP audio_prepare). ICNA35XX, CH13726A and SY7758 are upstream now in their own forms; ours are kept (60/120 Hz, Ultra Black, compatibles). Watch: 7.3 sets the DSP's MI2S mclk/bclk on sm8550 (speakers); suspend now uses 7.3's own geni UART and LPASS macro power-down. |
| ROCKNIX PR #3126 (SM8550 suspend/resume) | Upstream `next` has no working sleep on the Thor; the open PR does. |
| s2idle + `fw_devlink` cmdline (`0001`) | CPUs never reached cluster sleep; GPU power domains stayed on because `sync_state()` waited forever. |
| CPU0 idle quirk (`097-cpu0-idle`) | ROCKNIX disables CPU0's deep idle, so the CPU cluster could never power down. |
| Regulator suspend states in s2idle (`0219`, `0002`) | DT `regulator-state-mem` only applied to s2ram; the Thor sleeps with s2idle. |
| PCIe suspend OPP (`0220`, `0221`) | Without a small DDR vote in sleep, AOP firmware never returns to Linux (hang on wake). |
| USB autosuspend udev rule | The idle USB controller held a 1 GB/s USB→DDR bandwidth vote. |
| smp2p sleepstate (`9000`, `0003`) | Experimental: Android tells the ADSP when the CPUs sleep; mainline doesn't. |
| rsinput oversized RX (`1023`) | Gamepad dead after resume: handshake replies arrived in big chunks and were dropped. |
| SD UHS-I SDR104 (`0004`) | A caps mask kept the SD card at 3.3 V high-speed: 16.6 MB/s. |
| UFS HS-G5 (`1024`) | Internal storage ran at HS-G4: 1.5 GB/s instead of 2.6–2.8. |
| OLED Ultra Black (`9001`) | Android's Ultra Black fixes colour shift/mura at low brightness; Linux never sent it. |
| Charge limit (Kettle `1121` `1170` `1190` `1388` = `9018`–`9021`, `asgard-charge-limit`) | The firmware ignores the end threshold (our old `9003`); it takes a charge current. `1170`: charger updates no longer wake s2idle. |
| Azahar 2126.2 (`0005`) | Newer Azahar, kept by choice; it does **not** fix the Alpha Sapphire freeze (see the README's emulator table). |
| ~~No Steam (`0006`)~~ | FEX-Emu's 32-bit thunks failed to build with GCC 16.2, breaking the image build. Dropped 2026-10-10: Steam is back in the image. |
| melonDS menu bar (`0007`) | In two-window mode melonDS showed its Qt menu bar on one screen. |
| asgard package + boot tuning (`0008`) | Hostname, USB autosuspend, charge limit, CPU clock cap at every boot. |
| asgard.yml | ROCKNIX preconfigures Wi-Fi and keys by baking them into the image; Asgard keeps them in a file next to it. |
| Kettle sleep/GPU fixes (`9007`–`9017`; `9007` dropped with 7.3) | Kettle `1150` `1160` `1180` `1291`–`1293` `1350`–`1352` `1384` `1385` (see Projects to learn from). Flashed 2026-10-11 20:02: GPU boot DDR vote gone, 60 s RTC sleep resumes clean (pad handshake first try, Wi-Fi, audio). Sleep drain over ≥1 h not measured yet. |
| Bottom touch follows the panel (`thor-bottom-touch`) | Single-screen games run with DSI-1 off but its touchscreen on: a touch moved sway focus to the empty bottom workspace and RetroArch paused (`pause_nonactive`). The watcher enables/disables the touchscreen with every DSI-1 power change. Also: the AYN panel now powers DSI-1 off when it closes during a game. |
| No seat1 touch (`0022`) | ROCKNIX attached both touchscreens to seat0 and seat1, so every touch reached Asgard Home twice; the phantom second press stole taps (Home power button did nothing). Recurs if ROCKNIX's `start_steam.sh`/Heroic launchers die before undoing `seat seat1 fallback true`; Home resets it after every game (`backend.cpp`). |
| Display sleep hook | After resume the bottom panel lit up (black) even when it was off before sleep. |
| Bottom screen rotation + window rules | The bottom panel was portrait; games opened on the wrong screen or half the screen. |
| OLED idle blank | Burn-in protection: both screens off after 5 min without input. |
| Battery logger | Measures sleep drain and records charging state (a not-charging-after-sleep case had no data). |
| Speaker DSP | The speakers sounded thin and harsh without Android's JamesDSP preset. |
| Thor Settings | All system settings lived in ROCKNIX ES; Asgard needs them without it. |
| AYN button → Thor Panel | The AYN key did nothing on Linux; Home was only a hotkey modifier. |
| Panel FPS from sway (`sway-100.02`) | The panel's FPS came from window titles, so only melonDS showed one. sway now counts each window's new frames (`frames` in `get_tree`); the panel shows the busiest window's rate. Also the input for an auto-TDP later. |
| Asgard Home | ROCKNIX ES feels dated and isn't built for two screens; this is our own frontend. |
| Asgard Home as the only frontend (`0009`) | ROCKNIX ES is removed from the image; the frontend unit boots Asgard Home. |
| ADSP FastRPC remote heap (`0010`) | The ADSP sensors PD (gyro/accel) can't start without a reserved FastRPC heap. |
| ADSP sensors PD server (`hexagonrpc`) | Gyro step 2: starts the sensor core's QMI service. |
| Motion server (`asgard-motiond`, `0016`) | Gyro steps 3–4: accel/gyro as a DSU motion source; Azahar's 3DS motion input. Runs only when a game's Gyro option (or the menu's) is on (`asgard-perf-profile.sh`): streaming keeps the ADSP waking ~185×/s. |
| Trophies tab | RetroAchievements progress per game: ROMs hashed like RA does (rcheevos), matched through RA's Web API. |
| Kettle/Armada batch A (`9022`–`9031`) | Kettle `1060` `1110` `1200` `1210` `1220` `1250` `1270` `1280` `1383`, Armada `0048`: tsens wakes, haptics buzz after rumble, GPU queue priority, command-mode vblank timestamps, DSI clocks off the PLL when the screens are off, ICE/PCIe/ath12k fixes, GPU load in debugfs. Picked by dry-running every Kettle/Armada patch against our tree (2026-10-12). |
| MCU rail off in sleep (`9032`–`9033` Kettle `1310` `1311`, `0024`) | `vdd_mcu_3v3` was always-on: the gamepad MCU and both stick-LED controllers stayed powered through sleep. |
| Fan quiet in sleep (`9034`–`9035`, Kettle `1300` `1410`) | The 1 Hz RPM timer and tach IRQs kept waking s2idle (Kettle: blocks CPU cluster collapse). |
| USB PHY pipe clock (`9036`) | One PHY init timeout (a USB-C cable wake) disabled `pipe_clk` twice; every later resume then failed (`-110`) and the controller held its 1 GB/s DDR vote through sleep until a reboot. |
| Default output follows the jack (`0025`, WirePlumber rule) | ROCKNIX's `hdmi_sense` pinned the first sink at boot (our speaker EQ filter), so headphones never took over; and ALSA ranked the speaker above them. |
| Boot volume skips the EQ filter (`0045`) | The boot `volume` call ran right after `0025` cleared the default, so `@DEFAULT_SINK@` was the speaker EQ filter: it stayed at 65 % under the real sink's 65 % (quiet until an EQ change restarted PipeWire). Now the filter's device gets the volume; the script waits for it (~5 s: at boot it can register after the filter, which had put the filter back at 55 % under the speaker's 55 %) and resets both filters to 100 % on every call. |
| Gunyah watchdog driver (`0026`, `CONFIG_GUNYAH_WATCHDOG=y`) | Probe: shows whether the hypervisor has a watchdog (a `watchdog` under `/sys/class/watchdog`), a suspect for the restart on wake from full SoC collapse. The driver stops it at probe and across suspend. |
| Game-aware battery and sleep logs (`playlog.py`, `battery-log.sh`, `asgard-sleep-audit`, `asgard-charge-fix`) | Native ports and PC apps were logged as "menu". Home's launch record (`/run/thor-playing.txt`) now names the game, emulator and core; sleeps log DDR residency and save interconnect/regulator/genpd summaries; the game is SIGSTOPped through a lid-closed cable wake. |
| EQ filters at 100 % (`state.restore-props = false`) | While the speaker EQ was the pinned default, the volume keys moved it; a stale 45 % (−21 dB) stayed behind. |
| Speaker/headphone EQ, AutoEQ, Joey (`asgard-eq.py`, `eq/`) | Selectable EQ. Joey's Retro Handhelds JamesDSP preset as a minimum-phase FIR (`gen-speaker-ir.py`) + width-2 widener + `asgard-limiter` (our LADSPA lookahead limiter: PipeWire has none, and the preset adds +15 dB). PipeWire 1.2.6's parametric-equalizer module ignores node names, so AutoEQ files become biquad filter-chains. |
| Home sounds via `pw-play` | `QSoundEffect`'s audio thread once spun at 100 % holding a lock the UI waited on: Home froze. Qt Multimedia is gone. |
| Battery report, charger chimes, scraper | Settings → Hardware → Battery; `charger-in`/`out` on the charger's online flag (the battery reads "Not charging" at the limit); Select → Scrape this game. |
| GPU stale RPMh votes (`9039`, dropped with 7.3) | Upstream [d9108bfdb746](https://github.com/torvalds/linux/commit/d9108bfdb746edacdb05bd27959a4ae63c6c7f3f), not in 7.2: an inverted check left the GPU RSC awake after any GPU use, holding DDR at 1555 MHz (4224 after Eden) through sleep. Now 200 MHz. |
| Mesa 26.2.6 (`0048`) | ROCKNIX's 26.2.4 → 26.2.6 (bugfix releases: Turnip cache-invalidate fixes, Zink/kopper swapchain fixes). Brilliant Diamond's red/green triangles are gone without `TU_DEBUG=flushall` (Flush GPU caches off). |
| LPASS released in sleep (`9047`, replaces `9040`) | Armada PR #723: upstream 7.3 PM-clock conversion of the wsa/va/tx/rx macros, macros + SoundWire + LPI pinctrl force-suspended across system sleep, and the board I2S clock dropped at suspend (rewritten for our `sc8280xp.c`). Lets AOP collapse CX. |
| Syscon XO (`9041`) | From x1e-sleep: syscon kept TCSR's parent `bi_tcxo` prepared. |
| UFS PHY QREF supply (`9048`, `0033`) | Kettle 1402: the UFS PHY's reference-clock buffer on L1E gets a 30 mA load, so a wake doesn't fail PHY calibration ("Failed to calibrate PHY: -110", then all I/O fails). |
| Bottom panel timings (`9046`) | CH13726A on Android's DT timings (60 Hz, 12/4/12 porches) plus a 120 ms wait after sleep-out. Didn't cure the bottom-screen flicker. |
| logind watchdog off (`systemd-logind.service.d`) | After a long s2idle, systemd's 3 min watchdog killed logind on resume and NetworkManager left Wi-Fi unavailable. |
| Saved headphone EQ profiles (`asgard-eq.py`) | Every headphone found keeps its profile; Settings > Audio cycles Thor tuning / Off / saved names, "Your headphones" lists them. |
| Deep-sleep test switches (`9037`, `9038`, `9042`) | Runtime switches; `pcie_qcom.suspend_floor` is off by default since 2026-10-16 (=1 restores the floor), the rest off by default: `qcom_aoss.aosd` (AOP `aoss_slp`), `pcie_qcom.suspend_floor`, `qcom_aoss.send` (raw AOP message), `asgard_ddr_wake.enable` (Android `dcvs_fp` MC4/SH5 votes). Driven by `aosd-test.sh`. |
| Reset forensics (`9043`, `0027`, `0029`, `0030`) | XBL log in debugfs (reset reason), ftrace for RPMh traces, pstore console + 4 MB ramoops. Debug only; see Deep sleep plan step 8. Since 2026-10-15 reading `xbl_log` faults (synchronous external abort, the reading `cat` is killed): don't read it unless debugging a reset. |
| Wi-Fi PCIe link off in sleep (`0031`, `9045`) | The root port had no driver (`pcie_ports=compat`) and advertised hot-plug, so it never left D0 and the link, controller, PHY and rails stayed on through sleep. Now D3cold; see Deep sleep plan. |
| LDO E1/E3 off in sleep (`0032`) | What Android's sleep set does (PCIe/USB/UFS/DSI PHY rails). Retry of `0028`, which hung while the PCIe link was still up. |
| In-game menu for RetroArch and Steam | Home opened RetroArch's own menu and Steam's Quick Access directly. Now Home opens ours (bottom screen) everywhere except PPSSPP/ARMSX2/AetherSX2. RetroArch: paused over its network command port (`PAUSE_TOGGLE`), with RetroArch menu, quick save/load, screenshot, restart. Steam: `steam-pad-profile.py` maps Home to F20 (Steam never sees it, `thor_ayn_button.py` opens our menu); Steam overlay / Quick Access are injected with InputPlumber's `SendButtonChord`, which skips the profile. |
| Back to Home (`asgard-background.py`) | Leave a game without quitting: its windows go to sway's scratchpad and its processes are SIGSTOPped; Home's first tile returns to it. Starting another game asks to close it first. The old "Jump back in" tile is gone. |
| gen1recomp on the top screen (`thor-sway-rotate.sh`) | LÖVE re-creates its window at every launcher↔game switch; with focus on the bottom screen the launcher (and its quit X) opened there. |
| Board-level sleep drain (`0049`, `asgard-fan-sleep`) | Armada `431bf57` / `0a201e5`: bob1 drops to LPM in the sleep set (its loads are off or idle), and the unused WSA2 macro is disabled (bound, it held q6prm TX MCLK votes that kept the ADSP waking). The fan's 5 V rail stayed on through s2idle (pwm-fan mode 1 keeps it on with the fan stopped): mode 3 for the sleep turns it off. |
| Bottom screen 120 Hz (`9059`) | Android lists 120/60 Hz for the CH13726A and its dyn-clk (1011/505 Mbps) is exactly the 12/4/12 timings at 120/60 Hz; the driver only offered 60. Settings > Display > Bottom screen > Refresh rate (`asgard.refresh_bottom`, default 60). |
| Top panel full brightness range (`9060`) | The backlight stopped at 3413 of the 12-bit DCS range. On full white the panel current kept rising to 4095 (+70 % over 3413), so the cap cut the top of the panel's range. |
| Per-screen white balance (`asgard-gamma`) | The two panels' whites differ (the bottom is warmer). A wlr-gamma-control client holds each screen's DSPP gamma ramp (warmth/tint per screen in Settings > Display, `asgard.warmth.*`/`asgard.tint.*`); no GPU cost. Default bottom tint +10 (green ×0.80), measured with a webcam to match the top at 50 % brightness. The top panel crushes its shadows (grey 128 at 20 % of white vs the bottom's 52 %); `asgard.contrast.*` sets a ramp exponent per screen, default 2.0 on the bottom, which put it on the top's curve within 0.02 at every measured level. AYN's Android ships no colour calibration (QDCM tables all identity). |
| Ultra Black switchable (`9061`) | `9001` always sent AYN's Ultra Black, which is part of why the top crushes its shadows (mid-grey 20 % of white with it, 30 % without; the screen is also ~25 % brighter without it). Now a `panel_chipone_icna35xx.ultra_black` parameter read at every panel init, set from Settings > Display > Top screen > OLED Ultra Black (`asgard.ultra_black`, default on; Android's off bytes from its live DT). `asgard-gamma`'s bottom contrast default follows it (+10 on, +6 off, both matched by webcam) and retries a screen that was off when it started. |
| Default root password `asgardos` | `system.cfg` already set it for the root login, Samba and Syncthing at every boot, but the build's `ROOT_PASSWORD` still said ROCKNIX's `rocknix`. Now both agree, and the README documents it. |
| In-game Performance tile | Tuning a game's clocks meant quitting to its Settings page and restarting to see the effect. The in-game menu now has the same CPU and GPU cap rows (`Settings.qml`'s `optionRow`), saved to the game's keys and applied with `asgard-perf-profile.sh cpu` on leaving the page or the menu. |
| Updates keep emulator settings | `post-update`, inherited from ROCKNIX, deleted `/storage/.config/melonDS` and overwrote RetroArch's core options on every update, so a user's changes to them were lost (UPD-4). It now adds only the keys the image gained, and `test_post_update.py` runs the real script against a fake `/storage`. |
| Home's settings writer | `Backend::setSetting` deleted `system.cfg` before renaming the new one over it, replaced the file with one key if it couldn't read it, moved the key to the end, and took no lock against the shell's writers (CFG-4). `settings_file.h` writes atomically, in place, under the shell's lock, and is tested by `test_settings_file.sh`. |
| Sleep mode setting applies | Settings saved `system.suspendmode` and then ran `suspendmode`, which compared against that same key and did nothing. The SM8550 quirk also forced `SuspendState=mem` and turned `off` back into `mem` at every boot, so Light sleep and Screen off only never took effect or never lasted (PWR-11). `suspendmode` now always writes `sleep.conf`, and the quirk leaves it alone. |
| Power key on screens that are off | `power-handler` only knew its own blank flag, so a press with the screens off from the idle timer or Home's X suspended the Thor (PWR-10). It now checks the blanker's marker and sway, wakes the screens, and tells Home. |
| Bypass charging's floor | The loop charged at exactly 20 %, and a Thor asleep on the cable below 20 % charged on to full, because the loop is frozen and nothing woke it (BAT-2). The charge limit's RTC alarm now aims at the floor when bypass is on. |
| OpenBOR's kill data | `start_OpenBOR.sh` had no `set_kill`, so OpenBOR, the openbor system's default, had no working Quit or Back to Home (GAME-2). |
| Freeze report with no snapshot | A boot that froze before its first sleep, game launch or shutdown left no report, because the report needed a journal snapshot and boot had already moved the previous one away (LOG-2). It now leaves a short report that points at `events.log`. |
| No way to build secrets into an image | ROCKNIX's recipes could still write `LOCAL_WIFI_*` and `LOCAL_SSH_KEYS_FILE` into any image not built through `build.sh`, and `post-update` copied them to `/storage` (DEV-16). All of that is gone. |
| OpenGL driver option tells the truth | The option assumed unset meant freedreno, but the SM8550 quirk puts every game on Zink (confirmed on a Thor). So choosing Zink did nothing, freedreno couldn't be chosen, and the row was mislabelled. Unset is now documented as Zink, and a game or system can choose freedreno (GPU-3). |
| Bluetooth pairing scans and lists devices | Pair a new device never started a scan, and the agent only pairs while scanning, so nothing could ever pair (inherited from ROCKNIX; NET-1). It also offered headphones but only accepted controllers. Settings now scans while the page is open and lists named devices to pick from. The agent also pairs a device picked by address whatever its type, keeps late names, and reads `Paired` and `Connected` correctly. It acts on the pick itself rather than on the device's next event, which a device sitting still may never send (it hung a real pairing on a Thor), and runs one pairing per device at a time. |
| Battery logs: resting voltage and capacity | Above about 65 % the gauge's level and `charge_counter` run behind the measured current (2.6x at "80 %", 2026-11-02), and "80 %" rests at 4.24-4.29 V, so the logs couldn't say how full the battery really is or whether a sleep's reading was real. `battery-log.csv` now records `ocv_uv` and `charge_full_uah`, `sleep-audit.csv` `ocv_start` and `ocv_end`, and each `charge-fix.log` line the current, voltage and resting voltage, since charging mostly happens asleep where nothing is sampled. |
| Radios come back after screens off | With a game's Bluetooth or Wi-Fi set off while the screens are off, a block that failed or was still running when the lid opened left that radio off for good, and Connect and the Bluetooth toggle couldn't clear it (Bluetooth on a Thor with headphones connected, 2026-11-02; BAT-3). `asgard-screens-off.sh` now notes a radio before blocking it, and runs one step at a time. Checked on a Thor: Bluetooth comes back. With headphones connected the block seems to take over 10 s, the likely cause, and a lid opened during it waits that long. |
| Bluetooth Connect says why it failed | Connect and Disconnect gave no message on failure and could wait forever, and the device's page kept its state from when it was opened (NET-1). They now time out, the page shows what went wrong and follows the current state. |
| Radios while screens off: an OS-wide row | The Wi-Fi and Bluetooth options for a game that keeps running existed per system and per game only, and an unset row said just Default (OVR-1, OVR-2). Settings > Performance now has one row for each, on by default, and an unset row names its value. |
| Bluetooth reconnects after screens off | When the screens brought a blocked Bluetooth radio back, nothing reconnected the headphones: bluez doesn't, and Connect had to be pressed (on a Thor, 2026-11-02; BAT-3). `asgard-screens-off.sh` now notes what's connected before the block and reconnects it once the radio is up. |
| Home's profile while a game waits | Back to Home left the game's caps, cores and fan on in Home, and a lid or power press could put them back on later (OVR-4, PERF-3). Back to Home now applies the menu's, and returning applies the game's before it continues. The gyro and EQ stay the game's. |
| Screen overrides per game and system | Refresh rate, brightness, colour and Ultra Black could only be set for the whole OS (OVR-2, MENU-5). They're now per system and per game, in Hardware overrides and in the in-game Performance tile, which became a grid of pages to stay within five rows. They apply live and only when a value changes, and go under `/run`, so Settings' values stay. Changing Ultra Black cycles the top panel. |
| Lid reopened while going to sleep | The lid wakes the Thor only on its open edge, armed late in the kernel's suspend, and nothing cancels a sleep under way. A lid opened in the seconds it takes to go down (up to 15 more in the post-wake Wi-Fi hold, screens already dark) was lost, and the Thor slept with the lid open until the power button was pressed (on a Thor, 2026-11-06; PWR-13). power-handler now notes a lid close; the hold ends when the lid opens again, and a last pre-sleep hook arms `wakeup_count` with an RTC alarm 2 s out, which cancels the suspend or wakes it right after. |
